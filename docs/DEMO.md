# Демо: сценарий видео (до 3 минут) и план презентации (до 10 слайдов)

Здесь — заготовки для материалов сдачи. Видео и слайды нужно записать/оформить самим: код сервиса этого не делает.

## Сценарий видео (≈ 2:40)

Подготовка: `python -m dekanat serve`, открыть http://127.0.0.1:8000, браузер на весь экран. Примеры документов лежат в `data/samples/` и показаны на пустом столе справа — клик по примеру сразу запускает проверку.

## План презентации (10 слайдов)

1. **Титул.** «Онлайн-деканат» — цифровой секретарь: фото документа → ответ с пунктом Положения. Команда, ссылка на репозиторий.
2. **Проблема.** Деканат вручную читает фото справок, переписывает данные, ищет правила; студент ждёт и уточняет. (Из ТЗ: три шага, ответ приходит поздно и без основания.)
3. **Решение одним пайплайном.** Схема: фото + вопрос → OCR → карточка полей → поиск по Положению → ответ + источник + подсветка. Три вида ответов.
4. **Демо №1: документ в порядке** (скриншот: п. 3.2, подсветка полей).
5. **Демо №2: чего-то не хватает** (скриншот: «Не хватает даты выдачи и печати вуза… п. 3.4»).
6. **Демо №3: ответа нет** (скриншот: «Сколько стоит обучение?» → честный отказ). Подчеркнуть: ответ собирается только из найденного текста.
7. **Плохие снимки.** До/после: выпрямление, тень, блики, поиск листа, перебор вариантов предобработки; цифры из README (точность по уровням порчи).
8. **Новый тип документа без кода.** Фрагмент YAML + результат; автоопределение типа; подсветка найденных полей.
9. **Стек и ограничения по ТЗ.** Tesseract + OpenCV + FastAPI, правила и поиск по Положению на CPU, внешние API не используются; опционально локальная модель через Ollama. Ноутбук без GPU: 1–3 с на страницу.
10. **Качество и что дальше.** Таблица метрик на синтетическом наборе, честные оговорки (нет данных организаторов, эвристика подписи/печати), план: tessdata_best/EasyOCR, Telegram-бот.
